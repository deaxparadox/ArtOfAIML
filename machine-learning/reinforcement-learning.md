# Reinforcement Learning

See [Types of Machine Learning](types-of-machine-learning.md) for where reinforcement learning fits among the other categories — this chapter goes deep into how it actually learns.

## What is it?

Reinforcement learning is the family of techniques where an agent learns by taking actions in an environment and receiving a reward signal, adjusting its behavior to maximize cumulative reward over time — with no fixed dataset of correct answers, unlike everything covered in the previous three chapters.

[Types of Machine Learning](types-of-machine-learning.md) framed this as "learning to ride a bike — nobody labels each movement correct or incorrect, you just feel the outcome and adjust." This chapter is about the actual mechanics of that adjustment: how does an agent turn a stream of rewards into a better policy?

## Why does it exist?

[Types of Machine Learning](types-of-machine-learning.md) already flagged RL's core distinguishing trait: no fixed dataset exists ahead of time, since the data — which actions lead to which rewards — is generated by the agent's own actions and only revealed over time. That chapter also warned RL is usually a last resort, not a first choice, because it needs a safe environment to explore in. This chapter goes deeper into *how* an agent learns from that trial-and-error interaction, since the mechanism differs fundamentally from anything in supervised or unsupervised learning: there's no single correct action to imitate, only a reward that arrives after the fact.

**Explore vs. exploit — a decision unique to reinforcement learning.** A supervised model, once trained, just applies what it learned. An RL agent has to continuously choose between exploiting the best action it currently believes in (to maximize immediate reward) and exploring a less-tried action (to find out if it's actually better than currently believed). Too much exploitation risks getting stuck on a mediocre action forever; too much exploration wastes reward chasing options already known to be worse.

## How does it work?

An agent repeatedly observes a state, chooses an action, receives a reward, and updates its estimate of how good that action was. Over many repetitions, those estimates converge toward their true expected reward, and the agent's policy shifts toward consistently better choices. **Epsilon-greedy** is a standard, simple strategy for the explore/exploit trade-off: pick the currently-best-known action most of the time, but pick a random action a small fraction of the time (`epsilon`), to keep exploring.

## Example

A real, from-scratch multi-armed bandit: three arms with hidden true reward probabilities the agent is never told directly, learning purely from trial and error:

```python
import random

random.seed(0)

true_probs = [0.2, 0.5, 0.75]  # hidden from the agent
n_arms = len(true_probs)
counts = [0] * n_arms
estimates = [0.0] * n_arms
epsilon = 0.1

total_reward = 0
for t in range(2000):
    if random.random() < epsilon:
        arm = random.randrange(n_arms)          # explore
    else:
        arm = estimates.index(max(estimates))   # exploit

    reward = 1 if random.random() < true_probs[arm] else 0
    total_reward += reward
    counts[arm] += 1
    estimates[arm] += (reward - estimates[arm]) / counts[arm]

print(estimates)  # -> [0.191, 0.403, 0.763]
print(counts)     # -> [110, 62, 1828]
```

After 2,000 trials, the agent's learned estimates — `[0.191, 0.403, 0.763]` — closely track the true, hidden probabilities `[0.2, 0.5, 0.75]`, purely from observing rewards. It pulled the best arm (true probability 0.75) 1,828 out of 2,000 times, 91% of the time, without ever being told which arm was best or what the true probabilities were. The average reward per trial, 0.72, sits close to the best arm's true value — the agent converged to near-optimal behavior through nothing but trial, error, and the epsilon-greedy trade-off.

## Where is it used?

Game-playing agents, robotics, resource allocation, and recommendation systems optimizing for long-term engagement rather than a single prediction — anywhere the right action has to be discovered through interaction rather than read off a labeled dataset.

## Advantages

- **Learns purely from interaction**, needing no labeled dataset at all — as the example shows, the true probabilities were never given to the agent directly.
- **Optimizes for long-term cumulative reward**, not just the immediate correctness of a single prediction.
- **Adapts to an environment that can change**, since it's continuously updating its estimates from ongoing experience, not a fixed training set.

## Limitations

- **Needs a safe environment to explore in.** [Types of Machine Learning](types-of-machine-learning.md#limitations) already named this: you can't let a real pricing agent "explore" by randomly overcharging real customers the way the bandit example above freely tried every arm.
- **Convergence takes many trials.** The example above needed 2,000 trials to converge with just three arms; real environments with far larger action spaces need proportionally more.
- **The explore/exploit trade-off has no universally correct setting.** A fixed `epsilon` like the one used above is a simple choice, not necessarily the best one for every problem.

## Production considerations

- **Exploration in production means real actions with real consequences**, not a cost-free simulation. A production RL system needs deliberate limits on how much it's allowed to explore, and where.
- **Reward signal design is itself a critical, easy-to-get-wrong decision.** An agent optimizes exactly the reward it's given, not the outcome a person actually intended — a poorly specified reward produces a well-optimized agent doing the wrong thing.
- **Convergence isn't permanent.** If the environment's true reward structure shifts (a real-world equivalent of the bandit's hidden probabilities changing), an agent's learned estimates become stale and need to keep updating, not just converge once and stop.

## Common mistakes

- **Reaching for reinforcement learning when historical labeled data already answers the same question**, paying RL's exploration cost and slower convergence for no real benefit — the exact "usually a last resort" point [Types of Machine Learning](types-of-machine-learning.md) already made.
- **Under-specifying the reward signal**, leading an agent to optimize a proxy that technically satisfies the reward but misses the actual intended outcome.
- **Assuming an agent's exploration is free**, when in production, every explored action is a real action with a real cost or risk.

## Interview questions

### Basic

- What is the explore/exploit trade-off, and why does only reinforcement learning face it?
- What does epsilon control in an epsilon-greedy strategy?

### Intermediate

- Why does reinforcement learning need a safe environment to explore in, and what happens if that safety constraint is violated?
- Why did the bandit example need 2,000 trials to converge on just three arms?

### Advanced

- Design a reward signal for a real-world recommendation system, and identify one way an agent could technically maximize that reward while still doing the wrong thing.
- How would you adapt an RL system whose environment's true reward structure changes gradually over time, without retraining from scratch on every change?
